## 当前架构的合理性审查

### 保留的合理部分

原生 Android + 无框架 Web 适合当前体量；Workers/D1 支持统一数据与服务端权限；地点和个人高德凭据分离是关键边界。公共投稿经人工审核，可以在初期缺乏自动内容治理能力时控制风险。开源数据导出应继续保留。

### 本轮已修复或加强

| 优先级 | 发现 | 修改与证据 |
|---|---|---|
| P1 | 新增可选字段未进入 Web 导出，备份不完整 | 显式公开白名单补齐字段与评分摘要，CI 逐字段断言且验证不含 Key |
| P1 | 我的投稿固定截断100条，旧内容不可管理 | 服务端时间+ID游标、双端完整读取，CI 103条同时间戳无丢失 |
| P1 | 评论 UUID 排序不是时间顺序 | 时间+ID双键游标，CI 101条相同/不同时间分页 |
| P1 | 评价无作者归属，不能安全本人撤回 | 增内部 user_id，公共接口只返回 canDelete；旧匿名归属不猜测 |
| P1 | 撤回后若硬删记录会重新评分 | 使用软撤回且清空文字，原唯一约束仍生效，CI 删除后重评429 |
| P1 | 公开内容缺举报审核闭环 | 双端举报、服务端审核员权限、隐藏/恢复和审计，CI越权403 |
| P1 | 举报堆积/恶意举报风险 | 服务端每账号每日20条、同目标去重；举报不会自动下架 |
| P2 | 单条5分可压过大量评价的4.6分 | 口碑排序使用 (总分+17.5)/(评价数+5)；原始均分仍展示，避免混淆 |
| P2 | 选店只有搜索和大类，无法保存决策 | 双端筛选、预算、清单、足迹、随机和分享 |
| P2 | 输入和详情刷新重复重建地图标记 | 搜索防抖，标记集合变化时才重绘；需要进一步大规模性能测量 |
| P2 | 网络异常裸 JSON 错误/无限等待 | 可读错误、分类型超时、评价重试、公开列表保留与缓存 |
| P2 | 表单默认5分会制造无意识好评 | 双端评分改为显式选择 |
| P2 | 浏览附近定位会触发投稿流程 | 浏览定位与投稿定位分别处理，定位不持久化 |
| P2 | 固定使用最新浏览器测试工具 | CI固定版本，减少无关依赖变化；不在本地跑浏览器测试 |

### 不应被功能数量掩盖的问题

- 共享密码不是稳定个人账户：清除设备身份会失去旧投稿管理权。收藏/足迹保持本机，不能虚称跨设备同步。更大规模应提供可恢复账号与会话撤销。
- 原 IP 限制会误伤校园出口，改用账号单独限额又会弱化先前规则。本轮保留用户要求并明示误限，新增账号约束只加强，不擅自放宽。
- GitHub PR 与 Releases 是外部运营依赖，审核时延、附件可用性与密文清理需要管理员流程；并非无限免费后端。未来迁移对象存储要保留加密、授权与历史引用。
- 原始用户内容可能包含自行粘贴的敏感信息，字段白名单不能自动识别所有秘密。教程和反馈继续提示不要填 Key/私密位置。
- 离线公开文本可能已被撤回/隐藏。联网成功后以服务器为准；缓存界面明确标为旧记录，不承诺离线内容仍有效。
- 当前仍全量分页后客户端筛选，适合初期校园规模；需要以真实地点数量和耗时评估服务端搜索/空间索引/虚拟列表，而非现在引入复杂基础设施。
- 聚合评分不是“经验证消费”的评价，不能暗示真实到店；同一用户不同天仍可评价是原需求决定，后续若改权重须统一产品规则。
- 指定 image2.5 与真实高德认证仍需可用模型渠道/个人 Key，不能用本轮功能优化虚报补齐。

## 验证与发布

所有编译、单元/集成回归、Worker打包与重点界面检查在 GitHub Actions 完成。本地只进行语法、配置、XML和差异检查；部署沿用用户已授权的 Workers 推送，先远程迁移再发布。不会向生产插入测试地点、评价或举报。最终结果追加于下文，失败和外部阻塞如实记录。
